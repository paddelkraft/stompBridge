# USB feature parity audit

Status on 2026-11-18. **H** means hardware evidence exists, **I** means implemented and covered by code or native tests, **U** means unverified in that firmware path, and **—** means unsupported or absent. A code path marked I is not a hardware claim.

| Feature | Default Pocket Master | Default GP-5 | Replacement Pocket Master | Replacement GP-5 | Evidence and remaining gap |
| --- | --- | --- | --- | --- | --- |
| Automatic USB identity | H | H | H | H | VID/PID registry in `src/devices/registry.cpp`; both identities observed in the experimental target. |
| USB connect and reconnect | I/U | I/U | H for repeated Pocket Master and cross-pedal reconnects | H for repeated cross-pedal reconnects | `src/usb_midi_transport.cpp`, `src/core/connection.cpp`. A diagnostic capture found three idle HCD pipes after Pocket Master detach because the client closed the device without releasing its MIDI interface. Releasing the interface first allowed root recovery without reboot. On 2026-11-18, serial capture observed GP-5 → Pocket Master → GP-5 → Pocket Master, with identity, MIDI interface claim, sync, and all 100 names confirmed after each attachment. Each unplug also produced an IN receive error and failed the in-progress sync before cleanup; long-run and rapid reconnects remain unverified. |
| Live preset selection | H | H | H for A and D | H | Device CC/SysEx in `src/devices/*/plugin.cpp`; physical mapping in `src/core/application.cpp`. Replacement Pocket Master confirmed P01 after A and P04 after D on hardware. |
| Live Drive, Delay, Reverb and tuner | H for effect switching | H for effect switching and tuner | H for three block state changes; tuner U | I/U | Device-specific CC mappings in both plugins and native tests. Pocket Master hardware capture confirmed Drive, Delay, and Reverb transitions to off. Tuner readback is unavailable in both, so its state is assumed. |
| Bank and physical switches | H in default controller | H in default controller | H for A, D and block switches; full timing U | I/U | `src/main.cpp`, `src/core/switching.cpp`, `src/next_usb_main.cpp`. Replacement Pocket Master switches produced confirmed readback; timing and all bindings still need physical acceptance. |
| Current preset and block readback | H in host/combined evidence | U in default combined firmware | H for one boot | H | Native readback fixtures; both replacement plugins confirmed on hardware. Default GP-5 sync timed out in prior captures. |
| Preset names | — | U | H | H | Both replacement plugins request the `12 40` directory in background and validate 106 CRC-checked fragments and 100 indexed records. Pocket Master hardware capture on 2026-11-17 showed index 0 `piranhas`, index 50 `PoketMastr`, index 99 `Bass Q`; GP-5 evidence is in `docs/gp5-patch-readout-2026-11-17.md`. |
| Current effect model names | — | U | H for current Drive/Delay/Reverb IDs and labels; full catalog U | H | Pocket Master live-state `0x3003` IDs decoded as Scream, Analog, Plate 2 on P01; user confirmed all three against the screen. Mapping for the other catalog entries is implemented from the public Pocket Master model map but awaits device-by-device verification. GP-5 models were hardware captured. |
| Sync status and errors | I/U | I/U | H for successful sync and disconnect failures | H for successful sync and disconnect failures | Replacement serial reports pending, confirmed, interrupted and failed in `src/next_usb_main.cpp`. Cross-pedal capture showed `transport-failed` for the interrupted session at each unplug, followed by clean interface/device cleanup and successful sync for the newly attached pedal. No controller reboot or panic appeared in the capture. Retry and sustained failure behavior need more physical checks. |
| Web UI | I/U | I/U | — | — | Default web app in `src/main.cpp` and `ui/`; replacement `stompbridge-next-usb` has no web adapter. Capability-driven replacement UI remains a separate stage. |

Pocket Master indices 0–49 use P01–P50 and indices 50–99 use F01–F50. GP-5 indices 0–99 use P00–P99. Slot labels remain available before name sync. Name requests use background output, and the output queue reserves two slots for live commands. Unknown model IDs remain unnamed.
